# 工具箱时间码与编辑器选区复用评估

2026-10-29；基于上游 `2.0dev` `f3dfb60a`。本记录区分已实现的选区保护与工具箱后续工作。

选区翻译和断句复用工具箱的服务商配置、模型请求与断句边界解析；时间码复用已有对齐运行时。编辑器保留独立的候选预览、工程绑定、异步冲突检查及撤销事务，工具箱保留文件处理和报告流程，不宜直接把整个文件工作流搬入编辑器。

| 工作 | 当前行为 | 2.0 建议与难度 |
| --- | --- | --- |
| 选区时间码补缺 | 本分支只向对齐器提交完全没有 items 的字幕；部分词项和零时长标点均跳过。重新生成已有时间码需用户确认。 | 已在选区入口保护；工具箱的补缺语义未因此改变。 |
| 选区翻译 | 译文不变时保留副轨 items；改变已有带时间码的译文前要求确认，替换后可撤销。 | 已在选区入口保护；真实服务和模型待验。 |
| 工具箱校对合并或拆分 | `maw/postprocess.py` 的 `_build_segments` 在重组输出上清除 items；现有测试也写明这一行为。选区目前没有校对功能。 | **中等**：原文无变化的合并可按顺序验证并拼接词项；改字需审查现有 `_reconcile_items` 的适用性；拆分必须选择合法词项边界并处理不能可靠映射的情况。需要设计失败提示及回退，不能简单复制全部 items。 |
| 工具箱断句零时长标点 | `maw/postprocess_resegment.py` 的 `source_units` 对零时长词项降级；某些后续重组会导致 items 丢失。选区当前发现降级时拒绝应用。 | **小到中等**：共享算法应支持合法零时长标点并保证不会产出零时长整句，同时检验顺序、文本和全部词项；再让选区复用改进后的协议。 |
| 工具箱时间码补缺 | 共享对齐器判断不完整时会整句替换原 items，部分覆盖或零时长标点也可能触发。 | **中等**：先确定全工程操作中部分词项的预期，保守方案为跳过并报告已有 items；若要只补缺字词，还需可靠映射并保留既有时间与元数据。需覆盖混合选区、报告与失败回退。 |

上述工具箱问题的核心代码在此次功能原基线与 `2.0dev` 相同，推迟到 2.0 不会自动修复。按当前需求可直接在 2.0 上规划共享算法修复，无需先做 1.x 兼容；涉及重组字幕时还要验证分组、稳定 ID、绑定和删词关联。本次没有修改工具箱的这些行为。

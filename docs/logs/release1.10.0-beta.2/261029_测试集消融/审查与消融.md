# 测试集审查与消融

基线：上游 `main`，`ee87a390`。目标调整为减少约 3% 的测试；本记录不代表整个测试集已经逐项审完，也未达到目标。

## 规模与口径

基线静态搜索在 `tests/` 下发现约 2,787 个 Python `test_` 方法和 1,882 个 JavaScript `test` / `it` 声明，后者包含浏览器测试；`scripts/esm-mechanical/` 另有 34 个静态声明，仅在显式实验或预演时运行。合计约 4,703 个声明。循环生成的测试、动态发现、跳过项和嵌套测试会使运行时数量不同，因此这只是粗略盘点，不是统一的实际执行用例总数。按这个粗略口径，五十项删除约占 1.06%，距离 3% 很远；不能以删除行数或者合并测试名冒充完成目标。被删浏览器取消超时测试的一个静态声明循环生成两个运行用例。

本机分批发现的现有 Python 用例为 2,740 项；根目录 Node 测试运行 986 项；Playwright `--list` 发现 995 项。加回本轮删除的 36 个 Python 方法、12 个 Node 用例和 3 个动态浏览器用例，可粗略还原同环境下的基线分别为 2,776、998 和 998 项；再加实验目录 34 个静态声明，约 4,806 项中减少 51 项运行用例（约 1.06%）。这是按删除量反推而非对基线重新完整收集，且实验目录仍是静态声明，不应与跨平台实际执行数混为一谈。

## 逐项判断标准

每个候选依次回答：

1. **入口和后果**：谁能通过受支持的用户、CLI、旧工程、构建、发布或维护入口触发？故障会造成什么可观察后果？不能仅因调用者是维护者就视为无用。
2. **实际保护**：测试输入、执行路径和断言能否发现该故障？mock 是否把关键被测行为替换掉？检查的是结果还是必须保留的内部写法？
3. **重叠与独有覆盖**：逐一核对另一项测试的入口、输入、平台、失败结果和 CI 执行范围；名称或断言相同不代表覆盖相同。删除前检查候选中的每个独有断言及其后果。
4. **收益和代价**：检查是否禁止了合法实现或未来扩展、只验证外部工具自身、造成明显维护成本；与丢失的独有保护一同判断。单纯使用源码快照、mock、历史数据或边界输入都不是删除理由。
5. **结论与证据**：分为保留、可删除、待核实。可删除须有具体的重复覆盖或不合理约束证据，记录仍保留什么以及失去什么；无法证实调用场景或替代覆盖时保留。3% 是工作目标，不是删除条件。

该标准不要求每项都直接模拟最终用户：测试运行器错把错误报告为成功、发布工具损坏包、旧工程不能打开，都会间接影响真实用户。替代覆盖并非必须位于同一测试层，但必须核对实际执行范围及其仍未覆盖的失败方式。

## 32 项设计需求与用户后果

文件为 `tests/test_thumbnail_cache.py`，下表省略公共 `test_` 前缀；全部保留。缓存可以重建，但错误复用旧源、回收用户文件、破坏已有缓存或突破磁盘预算仍会造成实际用户损失。

| 方法 | 设计需求与用户表现 |
| --- | --- |
| complete_base_opaque_assets_stored_zip_and_hot_hit | 完整 ZIP 可热命中、资源 ID 不泄露路径、错 revision/路径逃逸不能读资源 |
| no_base_asset_revision_is_stable_across_status_requests | 没有基础画面时连续查询也保持同一资源身份，图片请求不失效 |
| same_millisecond_same_size_source_replacement_invalidates_all_caches | 同大小/浏览器毫秒相同的替换仍识别新源，不显示旧视频 |
| owner_release_keeps_other_process_asset_pin | 一个窗口释放不能解除其他进程的保护，活跃图片不被驱逐 |
| physical_sqlite_page_cap_and_prefetch_pressure | SQLite 物理页上限真实生效，压力反馈阻止继续预取 |
| cleanup_only_registered_inactive_sidecar_and_excludes_current_source | 只回收登记且过期的缓存，当前源及未登记用户文件受保护 |
| cleanup_skips_unexpired_pins_and_reservations | 在用或生成中的缓存不被回收 |
| cleanup_does_not_recycle_replaced_file_and_base_read_refreshes_usage | 读取刷新使用时间，被用户替换的文件不按旧登记删除 |
| sidecar_budget_counts_registered_bases | ZIP 文件也计入预算，不能只统计数据库占用 |
| injected_pack_hook_receives_cancel_and_bounded_deadline | 打包遵循取消与期限，不能因注入接口丢失控制参数 |
| failed_persistence_after_source_change_keeps_old_session_namespace | 写入失败与换源交叠时不能把旧内存帧挂到新源 |
| cancel_during_sprite_packing_reaps_and_keeps_resume_frames | 打包取消后仍可恢复已生成帧，无需重复解码 |
| explicit_tool_path_reaches_probe_pack_and_cached_sprite_crop | 自定义工具路径贯穿探测、拼图和裁图，不能部分退回默认工具 |
| no_100_frame_cap_and_tail_count | 长画面网格不被任意 100 帧上限截断，尾部帧数准确 |
| cancel_partial_resumes_and_preserves_existing_complete | 中断可恢复，已有完整缓存不能被半成品替换 |
| coarse_and_partial_sprites_share_query_and_cross_session_resume | 粗网格与局部网格共同可查询，新会话继续恢复 |
| atomic_replace_budget_reuses_old_allocation_and_preserves_failure | 替换复用旧空间额度，失败保留原文件和登记 |
| concurrent_base_reservation_cannot_spend_replace_credit_twice | 两个生成任务不能重复花同一份替换额度突破预算 |
| cancelled_retry_preserves_sealed_partial_and_allows_added_coverage | 再次取消保留已封存内容，新增覆盖可追加而非回退 |
| retained_partial_return_uses_only_the_persisted_sprite_layout | 返回的布局必须与实际已保存文件对应，防止坐标引用未落盘图片 |
| cross_session_grid_reuse_and_actual_pts_asset_dedup | 跨会话复用网格，实际同帧去重，不浪费磁盘和解码 |
| symlink_registration_matches_resolved_source_namespace | 别名与真实路径共享正确源身份，不重复/错配缓存；需真实符号链接 |
| registration_replacement_at_entry_rejects_old_frames | 注册入口换源拒绝旧帧 |
| replacement_after_registration_check_keeps_old_namespace | 校验后换源仍不能把帧写入新身份 |
| source_replaced_while_extraction_rejects_registration | 解码期间换源不能发布过期结果 |
| disk_failure_reports_once_and_session_stays_usable | 磁盘失败只提示一次，当前会话仍能看已生成画面 |
| quota_protects_current_asset_and_does_not_reextract | 压力下保留活跃帧，不能反复驱逐/解码造成卡顿 |
| unknown_version_missing_assets_and_false_complete_are_misses | 不接受未知格式、缺图片或伪完整文件，允许重新生成 |
| manifest_file_budget_and_crc_corruption | 大小预算与实际 ZIP 损坏可识别，不返回错误内容 |
| atomic_windows_replace_retry_and_old_file_preservation | Windows 临时占用允许重试，永久失败不损坏最近成功文件 |
| output_candidates_and_bounded_nearby_preview | 允许已有输出位置，附近预览遵循范围限制 |
| deadline_does_not_mark_partial_complete_or_restart_failed_targets | 超时不标为完成，已知不可用目标不重复启动处理 |

32 项没有可证明应直接删除的保障。昂贵的解码假文件没有贡献这些断言的输入信息；原夹具本来就用 fake source、fake JPEG、fake probe/target extractor/sprite。补入空关键帧结果保持原“关键帧阶段没有可用帧”的语义，不关闭应用关键帧行为。`maw.thumbnails._run` 额外 guard 让将来的漏注入直接失败，不能再靠底层错误被吞掉蒙混通过。

## 改动与清理边界

只改该测试类 setUp/清理：注入 `extract_keyframes=[]`，添加媒体进程 guard；patch 和临时目录以 `addCleanup` 登记，成功及 setUp 失败都按逆序恢复。SQLite 连接、真实文件和 ZIP 仍逐例独立，不复用可变数据库、缓存产物或 HTTP 服务。生产代码、分组策略、超时、skip 白名单均未改，没有新增测试用例。

真实关键帧 PTS、密集源采样、关键帧预览登记/精确升级，以及播放取消/跨进程去重由原 `test_thumbnails.py` 与 `test_thumbnail_jobs_integration.py` 另验，不拿合成 JPEG 证明媒体解码正确。

## 下一批候选的取舍

当前剩余成本主要是实际路径/SQLite/原子操作。暂不做内存数据库、关闭同步或共享可变连接，它们会失去持久化与并发保障；原子替换重试仍使用原期限。待取得新的关键路径证据再研究。清单 VM 私有名耦合偏可维护性，未证明时间收益，不与此次资源降本混在同一修改。

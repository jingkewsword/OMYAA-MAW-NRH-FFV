## 第一性原理与逐例必要性

工具的核心交付是：将可审查的源清单生成可离线核验的页面，准确保留人的确认与反馈，并可导出交接。设计需求来自工具 README 的源/结果契约和交互说明，而不是测试当前依赖了哪些内部函数名。

当前清单专属集合为 Python 30、Node 17、真实 Chromium 9，共 56 项。下表每行对应一个现有用例，不把 subTest 或断言计为额外测试。全部保留；“可合并讨论”不等于已删除。测试文件及原断言均未修改。

## 可消融的准备与长期准入

- 清单独立范围用已有 `tools` 门禁的 `tools_scope=checklist` 精确运行 2 个 Python 模块与 1 个 Node 文件，不新增一套测试组；源目录仍带上自身真实 E2E。独立修改 Python/Node 测试维持原有消费者范围。
- 移除该范围的 editor/Launcher bundle 构建、应用 tsc、无关打包/重构工具回归与 Pillow/Ruff 前置检查。docs 仍运行导航、发布正文及其 37 项回归，不能因 tools 被收窄漏掉文档回归。
- CI 传递 scope、具体 spec 和 `application`/`real_media` 准备需求。清单独立范围不执行 uv 应用环境同步、不安装 FFmpeg/媒体字体，保留锁定 Node 依赖与真正 Chromium；`app=true` 仍表示必需执行的业务/工具 job，不能把没有应用构建误作整个 job 可跳过。
- 混入其他工具/应用/共享配置/未知路径时恢复完整 tools 或更宽的组；空 spec、混合应用 spec、完整浏览器与发布保留原应用/媒体准备。显式 `--pack tools` 默认全工具，CI 必须显式交接 scope。新增输出缺失、非法或与消费者矛盾时 Required gate 失败。
- 新测试先说明独立用户损失，再选生成器/脚本/真实浏览器层；同层新分支优先追加表驱动输入，不新增应用启动。增加新产品依赖必须更新这份依赖边界与隔离验收；不能为了继续使用轻量路径而 mock 掉真实集成。

后续可讨论 VM 的行为接口与合并局部重复输入，需先证明原故障组合仍检出；当前不直接删测试，不扩大为跨应用框架或逐用例路由表。

# 文档回归分层与解释器启动成本

维护者于 2026-10-15 授权继续推进测试优化；本轮在 `docs/test-suite-governance-20261013` 上从 `97f1d28d` 继续，该基线的 [CI 38744919374](https://github.com/jingkewsword/OMYAA-MAW-NRH-FFV/actions/runs/38744919374) 完整 Chromium 830/830 与所选门禁通过。文档降本部分改变检查入口的可调用方式及其测试组织；随后普通合入并发更新的 fork main，补齐新增清单工具的测试归属与 lint，见下方集成记录。

## 取舍与保留边界

原 22 个 `test_docs_check` 用例中，14 次调用会启动完整 Python 检查器进程。保留以下五次真实 CLI：固定中英文/空格/HTML 导航 fixture 的成功、缺图、错误锚点三种结果，以及同一历史断链的默认/严格模式文本与真实退出码。它们继续覆盖脚本入口、参数传递、stdout/stderr、JSON/Unicode 和成功/失败进程状态。

其余模式组合改为调用 `check_docs.main(argv)`，仍走同一个 ArgumentParser、真实 Git 文件清单/忽略检查、链接/结构检查、JSON/文本输出和退出码计算。测试捕获结果后继续使用全部原断言；不模拟检查结果，不改变文件枚举，不共享可变 fixture，不缓存目录或扫描状态。已暂存与未跟踪文件的 Git 读树/只读性用例保留；生产 CLI 无参数调用仍读取正常 `sys.argv`。

## 同集合成本

同机、同 Python 3.11、同私有临时目录、串行测试。原版测试从固定基线读取，优化版读取当前源码；除测试入口的进程组织外，断言与 ID 未改。

| 样本 | 原版 | 优化版 | 结果 |
| --- | --- | --- | --- |
| required runner 内层 | 11.254 秒 | 5.952 秒 | 两份报告完全一致，22 个 ID，零失败/错误/skip |
| 独立同进程计时复核 | 9.289 秒 | 8.041 秒 | 相同 22 个 ID，零失败/skip；同时实际计数检查器启动 14→5 |

确定收益是少启动 9 次检查器解释器；两次测量均缩短墙钟，但幅度明显变化，不承诺固定加速百分比、CPU/RSS 或 p95，也不外推为完整 CI 等量缩短。真实 Git 子进程和代表性 CLI 继续产生其必要成本。

原始 required 报告、计时脚本和对照 JSON 留在 `.artifacts/phase5-docs/`；完整输出仍由有界运行器保存。复核脚本只在忽略目录内，不作为新永久治理工具入库。

## 故障检出

在隔离副本内分别执行原版和优化版的原用例；要求都是断言失败，不能以导入/语法错误冒充检出。

| 注入故障 | 保留的检出用例 | 原版 / 优化版 |
| --- | --- | --- |
| 新断链不再使退出码失败 | 未登记日志中的新坏链仍失败 | 均检出 |
| 严格模式忽略历史坏链 | 默认与 strict 的真实 CLI 结果 | 均检出 |
| 直接跳过目标锚点校验 | 固定 Unicode/HTML 导航坏锚点 fixture | 均检出 |

22 个 ID 未减少；新断链、历史断链、日志 warning、关键文档索引、中文/HTML 锚点、JSON 输出和 Git 状态保持原保障。没有新增重测试、浏览器启动、依赖下载、retry 或 skip。

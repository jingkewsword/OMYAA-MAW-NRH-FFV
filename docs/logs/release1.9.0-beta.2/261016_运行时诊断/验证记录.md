# 本地运行时按需诊断

基线：上游 main fa5ae60c。范围：在现有运行环境设置中增加按需、只读检查；候选能力先在 fork Draft 评估，尚无上游采纳结论。

## 行为与取舍

- 通过现有 `ManagedRuntime` 获取位置、状态、解释器与子进程环境，直接执行 `RuntimeSpec.verify_command`；普通 local 与 MOSS 不混用环境。缺失、安装中或不完整时跳过，不触发安装状态自愈或修复。
- 每步最多 60 秒，为冷导入留出时间；独立子进程使用既有进程树管理，轮询与取消按操作 ID 隔离，一次仅允许一个检查。关闭 Launcher 发出取消并等待清理。
- 默认仅依赖导入，另一个按钮明确请求 CUDA 微量张量运算和同步。模型推理固定为未检查，无整体“模型可用”结论；CPU/MPS 无 CUDA 不代表环境损坏。
- 报告通过固定字段、已知代码与版本格式白名单生成，不回传原始异常、输出、路径、环境变量或硬件名称。导出使用既有原生保存对话框，只保存服务端已完成的报告，忽略前端传入的任意报告与路径。
- 不移植历史诊断旧 UI、重复配置、自动降级或安装能力；CLI、PR244 覆盖内容与旧标点方案不在本批范围。

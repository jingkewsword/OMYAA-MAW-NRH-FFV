# 本地运行时按需诊断核查

> 基线 main fa5ae60c；仅供 fork Draft 评估。自动化与人工验收分开，真实 CUDA、模型推理和打包尚未验证。

## 实现与审查结论
<!-- id: implementation -->

入口复用「本地模型 → 设置 → 运行环境」。local 与 MOSS 各用现有 registry、根目录、状态与安装自检命令；不开机自动检查，不维护另一套配置或包清单。检查只读，不修改安装与 manifest，不下载或加载模型。

导出仅包含固定字段与有限代码、版本号；不采集路径、硬件名称、环境变量、模型缓存文件或原始 stdout/stderr/异常堆栈。CUDA 成功仅代表微量张量运算与同步，不保证模型、显存或 CTranslate2/cuDNN 路径可用。

## 修复与提交记录
<!-- id: changes -->

实现内容为按需依赖导入、可选 CUDA 调用、每步 60 秒超时、按操作 ID 取消和 JSON 保存对话框；关闭 Launcher 取消并等待清理。安装、修复、扫描、模型下载与推理仍使用现有入口。

本批不推进 CLI 毫秒别名、PR244 已覆盖内容或旧标点入口。提交与验证记录见 [实施记录](验证记录.md)。

## 自动化验证结果
<!-- id: automation -->

详见实施记录中的定向 Python、Node 与浏览器结果。真实子进程的取消、超时与异常退出已测；合成 torch 模块验证 CUDA 分支，不冒充硬件验收。本机实际默认 local/MOSS 未安装，真实检查返回 runtime_missing 并跳过执行。

## 人工核验
<!-- id: manual -->

- [ ] **设置操作不会自动执行重检查**
  （操作）选择本地模型 → 打开设置的运行环境页 → 重新扫描 → 展开运行时清单。
  （预期）仍显示原有状态与清单；未点击诊断按钮时不出现运行中，也不额外启动诊断进程。
  <!-- id: explicit-trigger -->

- [ ] **普通本地环境与 MOSS 使用各自已有安装位置**
  （操作）分别选择普通本地运行环境与 MOSS，点击检查依赖导入；在已安装及未安装环境各观察一次。
  （预期）报告明确检查对象；已安装环境执行原有安装自检，未安装或不完整环境说明原因并跳过，不自动下载、安装或修复。
  <!-- id: selected-runtime -->

- [ ] **取消与关闭会清理本次检查并允许重试**
  （操作）冷启动检查时点击取消；另一次检查时关闭并重开设置；再启动检查后退出 Launcher。
  （预期）取消后显示未完成并恢复按钮；关设置后重开仍能看到当前检查；退出 Launcher 回收检查进程，无后台残留。
  <!-- id: cancellation -->

- [ ] **CUDA 基础检查与实际模型能力分开表达**
  （操作）先仅检查导入，再在具备 CUDA 的机器点击检查并测试 CUDA；在 CPU 或 MPS 环境也观察提示。
  （预期）第一次 CUDA 显示未执行；第二次明确成功、不可用或失败；不会显示模型已通过或把 CPU 环境判为损坏。
  （说明）仍需另用短音频验证实际模型；本批没有真实 CUDA 硬件验证证据。
  <!-- id: cuda-smoke -->

- [ ] **保存对话框导出可分享的固定字段报告**
  （操作）检查完成后导出诊断 JSON，先取消保存，再保存至自选目录并打开文件。
  （预期）取消不写文件；保存文件为有效 JSON，仅含版本、平台、对象和检查状态，不含用户名、路径、硬件名称、环境变量、原始日志或异常消息。
  <!-- id: report-export -->

- [ ] **中英文与明暗主题下诊断布局可读**
  （操作）切换语言和主题，在窄窗查看运行中与完成报告并使用键盘操作按钮。
  （预期）提示和结果正确翻译，按钮不溢出；相邻块垂直距离至少 8px。
  （说明）自动浏览器已测内部间距 10px、外部 20px，截图留在本机测试产物。
  <!-- id: layout -->

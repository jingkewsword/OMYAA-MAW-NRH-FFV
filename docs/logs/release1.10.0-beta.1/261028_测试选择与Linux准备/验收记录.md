## 必要性

修改 `editor-sticker-root.js`、`editor-sticker-overlay.js` 或 `editor-wiring-ass-frame.js` 时，旧选择器缩小到局部 E2E，却遗漏直接验证贴纸重载和原帧几何的已有消费者。新增的是族映射和现有策略方法中的输入，不增加浏览器用例，不靠测试数量快照守门。

固定历史 CI [39972867002](https://github.com/jingkewsword/OMYAA-MAW-NRH-FFV/actions/runs/39972867002) 的三个浏览器分片尚未开始测试便在 APT 准备期间达到二十分钟 job 上限，POSIX 的 FFmpeg 下载也耗尽十分钟。成功分片下载正常，进入真实浏览器并通过；缺失的三个分片报告继续被严格汇总拒绝。本次调整下载准备，不调整实际测试的断言期限、worker、分片数量或失败规则。

## 实现范围

`scripts/prepare_ci_apt.py` 只替换完整已知 Ubuntu archive/azure/security URL。普通归档使用官方 archive HTTPS，security URL 保留 security HTTPS；支持传统 sources.list、.list、deb822 .sources 及 runner 的 apt-mirrors.txt。发行版、组件、Signed-By、第三方源和签名验证保持。APT 改动仅发生于一次性 Linux CI runner，Windows 步骤与 release 工作流未改。

30 秒限制属于连接和数据等待，不能阻止持续低速下载，因此还保留独立的五分钟安装步骤上限。[APT timeout 的定义](https://manpages.ubuntu.com/manpages/tenacious/man1/apt-transport-http.1.html)与[禁用推荐包的官方配置](https://documentation.ubuntu.com/security/common-mistakes/unnecessary-packages/)为配置依据。没有新增包缓存、容器平台或通用重试框架。

editor workflow 增加无参数 `workflow_dispatch`，供草案存在合并冲突时在明确分支 head 上运行原完整选择兜底与门禁；push 触发仍只有 main。该结果证明分支本身，不代表它与最新 main 的合并组合。

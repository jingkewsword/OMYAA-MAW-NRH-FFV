## 保留的行为

服务器测试的通用 setUp 只有 `0123456789`、`abcdefghij` 等假媒体字节；原 FFprobe 解码失败后返回 None，缓存探测失败返回 false。现在在真实探测函数的调用边界显式声明同一夹具事实：只替换 `maw.project_io.probe_video_fps`、`probe_audio_tracks` 和该模块服务器类的 `_thumbnail_base_ready`，不替换 `enrich_project_media_metadata`、项目绑定 payload、保存和请求处理代码。没有伪造可播放媒体或新增探测成功值。

两个真实 libass 方法直接使用真实 FFmpeg，仍分别检查播放头边界、绿底像素、字幕出现/消失，以及实际视频的 RGB 字形和无字幕对照；仅补齐绿幕方法的 media 归属，不改其内容。保留 common 中 3 次原有假解码失败调用，用来继续走 FLV/最近工程的波形失败后读取源 ReaPeaks 路径，没有把整类所有外部调用统一替掉。

新 common 91 项在禁止 FFprobe 的诊断 guard 下通过；另把绿幕暂纳回同一个 92 项集合做 A/B，因此没有把 92→91 冒充同集合提速。93 个原测试函数（含全部断言、事件等待与清理）AST 逐项一致；改动仅限 setUp 和原有策略检查中的追加断言。现有 Project IO 元数据合并专项、真实缩略图服务专项和工程绑定并发专项在独立调用中通过，验证 patch 未替代这些消费者。

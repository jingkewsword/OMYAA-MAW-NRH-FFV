# 独立组继续与完整失败清单

本批接续按影响选测，在其已选范围内改进失败反馈。没有把普通改动升级为全库，也没有以历史浏览器红灯全部收绿作为前置。

## 实现与验收

- 本地执行不因前一独立组非零而提前结束；Python、Node 定向文件分别记录进度。小型三组中前两组分别退出 7、9，最后一组仍执行并成功，汇总保留三项真实退出码并最终失败。
- 构建或依赖准备失败只阻塞有明确依赖的组。受控构建失败时，独立治理测试实际执行，读取 bundle 的测试标为 `blocked`；不能将阻塞算成通过。静态映射无法覆盖任意动态依赖，缺少证据时保留实际运行的错误。
- Python 报告保留每个失败、错误及预期失败的完整明细；Node JUnit、Playwright 的所有错误、跳过及重试按其真实语义提取。300 个受控失败 ID 不截断。缺报告、缺用例和计数不一致明确记为证据不完整；Node 命令退出 0 而产生不允许的 skip，门禁仍失败且保留原退出码 0。
- 工作流以明确的准备结果控制依赖，独立检查在前面失败后继续。汇总将失败、阻塞和未运行分开。浏览器分片失败后仍尽量取回所有报告，集中保存每片全部错误；终端只展示有界摘要。
- 网站准备失败只影响分片发现中真正包含网站消费的单元；其他浏览器分片不被同一次网站失败取消。
- 修正运行器无条件更换临时卷：Windows 8.3 路径夹具依赖卷的实际能力，强行将系统临时目录搬到工作区可使其失效。现在继承调用者的有效临时目录，精确的缺能力失败政策继续保留。

本地正反例、三语言报告提取、既有运行器及工作流契约按本批影响验证。远端验收使用新候选提交单独记录；旧提交上的成功不代表本批通过。自动中断接续留待后续实现，不能把逐组落盘误写成已可安全恢复。

## 独立复核修正

审阅发现并修复三处过宽阻塞：浏览器按整份计划而非本片集合判断前置；临时 bundle 夹具被误认为仓库产物；全量准备失败跳过整套 Python。修复后，分片发现完成再判断具体文件的应用/媒体/网站需求；仓库根读取与临时夹具分开；全量受阻时独立 Python/Node 文件继续，原完整组仍明确未完成。六项针对这些实际触发的独立正反例通过，无未处置的阻塞项。未以历史全量或远端结果代替该复核。
